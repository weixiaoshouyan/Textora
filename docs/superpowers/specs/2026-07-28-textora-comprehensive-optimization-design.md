# Textora 全面优化设计

日期：2026-07-28

## 目标与约束

在保持现有功能、用户可见文案和快捷键兼容的前提下，按风险优先顺序改善 Textora 的安全性、数据可靠性、启动性能、编辑器体验和工程质量。当前工作区存在大量未提交改动；本次优化不重置、不覆盖与本任务无关的用户改动。

验收标准：

- 文件操作、外部工具和导出路径不能越过工作区边界；符号链接不能绕过边界。
- 自动保存、外部文件修改、会话恢复和窗口关闭流程在并发/重复事件下保持一致。
- 首屏和首次编辑不加载不必要的重型依赖，大文件不会导致主进程或渲染进程失控。
- 现有快捷键和核心编辑流程保持可用；关键 UI 具备键盘和辅助技术语义。
- 单元测试、类型检查、生产构建和端到端冒烟验证全部通过。

## 方案

### 1. 安全边界与数据保护

建立统一的同步/异步工作区路径校验。所有文件 IPC，包括读取、写入、创建、重命名、删除、监听、图片/二进制读写和导出目标，都先验证规范化路径，再验证真实路径；工作区根目录设置要求路径存在且为目录。修正 `is_directory` 的绕过，并拒绝指向工作区外的符号链接。

统一文本、图片和二进制大小上限。超过上限返回稳定、可识别的错误码/错误对象；读取端不把超限内容整块载入内存，写入端限制输入字节数。

AI 工具调用保留现有接口形状，但服务端忽略模型传入的工作目录，始终使用当前工作区。命令继续使用 `shell: false`、结构化参数、超时和输出上限；补充 Windows 命令解析、非法参数校验和进程结束幂等保护。

导出前校验目标路径。HTML 清理改为 DOM 解析级策略，移除危险元素、事件属性和 `javascript:`/危险数据 URL，同时保留 Markdown 图片所需的安全资源。

窗口关闭加入幂等令牌，确保重复的 close 请求只进入一次确认/销毁流程。

### 2. 可靠性与状态一致性

移除 store 内部定时器与 `useAutoSave` 的重复调度，保留单一自动保存调度器，并按活动标签重新安排计时。保存任务记录 tab id、内容版本和路径快照；异步返回时仅在快照仍匹配时更新状态。

文件监听保留现有去抖机制，新增自身原子写入临时文件过滤和来源判断。外部变化对未脏标签自动刷新，对脏标签沿用确认流程。会话恢复逐项验证路径、存在性和大小，坏条目不阻塞其他条目，并清理过期记录。

统一关闭状态为 `idle -> confirming -> closing`，取消或失败返回 `idle`。IPC 错误使用稳定结构，渲染层显示本地化可读信息，日志不写入 API Key 或完整文件内容。

### 3. 性能与启动体验

Shiki 首屏只保留文本回退，首次代码编辑或空闲时再初始化高亮器；语言继续按需加载。Mermaid、KaTeX 和导出模块保持动态加载。大文件关闭实时高亮及昂贵插件，但保留编辑、搜索、保存和现有快捷键。

搜索与目录扫描增加最大文件数、总字节数和取消标记。通过更窄的 Zustand 选择器减少输入造成的全树更新；分屏仅在开启后挂载。调整生产分块并验证打包资源路径，建立首屏、首次 Markdown、首次代码高亮和 10 MB 文本编辑基线。

### 4. 编辑器体验与工程质量

不改变现有视觉语言，补齐图标按钮标签、焦点可见性、弹层焦点陷阱、状态栏语义和错误状态。分屏右侧明确只读并修正滚动同步边界。主题/语言切换同时更新 DOM、编辑器实例和原生菜单。

清理乱码注释、README 编码和失效文件引用。对 IPC、AI 工具、ProseMirror 节点和事件边界使用窄类型，仅在第三方 API 边界保留必要转换。

## 测试策略

- 单元测试：路径与符号链接、大小限制、命令/cwd 校验、导出清理、自动保存竞态、外部修改、关闭幂等、会话恢复。
- 集成测试：IPC handler 的成功/失败结构和工作区边界。
- 端到端冒烟：启动、创建/打开/保存、源码模式、查找替换、主题切换、关闭未保存文件。
- 验证命令：`npm test -- --run`、`npx tsc --noEmit`、`npx tsc -p tsconfig.main.json --noEmit`、`npm run build`。
- 使用 Playwright 检查关键视口下非空白渲染、无明显溢出、焦点移动和核心交互。

## 分阶段交付

1. 安全边界和数据保护。
2. 可靠性与状态一致性。
3. 性能和启动体验。
4. 无障碍、类型收紧、编码清理和端到端验证。

每阶段完成后运行相关测试并保留可回滚的小范围提交；不修改用户已有未提交改动的意图或内容。
